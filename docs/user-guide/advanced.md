# User guide: Advanced

[New to GitHub](beginner.md) · [Intermediate](intermediate.md) · **Advanced**

**Who this is for:** You run repositories, organisations or migrations, or build on this catalogue's data.

**By the end:** Secure and automate repositories, plan moves between organisations without breaking anything, and reuse the catalogue's data and feeds.

## Steps

1. Review the security and supply-chain signals: secret scanning, Dependabot, pinned actions and branch rules. (in the catalogue: *safe* view)
2. Plan a move between organisations: the migration plan, the checks before and after, and what breaks on transfer. (in the catalogue: *plan* view)
3. Find legacy technology and technical debt by organisation, with the evidence behind each signal. (in the catalogue: *legacy* view)
4. Reuse the data: download feeds, the knowledge graph (SKOS, OWL, PROV) and the DCAT catalogue. (in the catalogue: *knowledge* view)
5. Trace every requirement to the checks that prove it, and every defect to its fix. (in the catalogue: *trace* view)
6. Link straight into the catalogue: #repo=<account>/<repository>, #org=<GOV.UK slug>, #legacy=<GOV.UK slug>, #account=<GitHub account>.

## Words you'll meet

- **GitHub Actions:** Automated workflows that run on events such as a push or pull request: tests, builds, deployments.
- **Rulesets and branch protection:** Rules for what may be merged and by whom, such as required reviews and checks.
- **Secret scanning and push protection:** Finds credentials committed to a repository and can block them before they are pushed.
- **Dependabot:** Raises alerts and pull requests for vulnerable or out-of-date dependencies.
- **Transfer:** Moving a repository to another account. GitHub redirects old links, but Pages, packages and some settings need extra steps.
- **REST API:** The programmable interface to GitHub, used for audits, inventories and automation.
