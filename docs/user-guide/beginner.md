# User guide: New to GitHub

**New to GitHub** · [Intermediate](intermediate.md) · [Advanced](advanced.md)

**Who this is for:** You have never used GitHub, or you've only followed a link to it. You don't need to write code.

**By the end:** Understand what GitHub is, read a project's page with confidence, and use this catalogue to find code that matters to your work.

## Steps

1. Learn the five words that matter: repository, README, commit, issue and organisation. The list below explains each in a sentence.
2. Search this catalogue in everyday words, such as 'benefits' or 'school data'. Results are grouped and explained in plain English. (in the catalogue: *search* view)
3. Open a project's profile. Start with the summary at the top: what it does, who it belongs to and whether it's still looked after. (in the catalogue: *profile* view)
4. See who a project belongs to, from the GitHub account up to the government department. (in the catalogue: *family* view)
5. Look anything up in the plain-English guide when a word is new. (in the catalogue: *glossary* view)
6. When you're ready, follow GitHub's Hello World exercise below. It takes about 15 minutes and you can't break anything.

## Words you'll meet

- **Repository (repo):** A folder for one project: its files, its history and the conversation about it.
- **README:** The front page of a repository. It should say what the project is, who it's for and how to use it.
- **Commit:** A saved change, with a note saying what changed and who changed it. The history of commits is how you can trace any change.
- **Issue:** A note on a repository to report a problem, ask a question or suggest an idea.
- **Organisation (account):** A shared GitHub account for a team or department, which owns its repositories.
- **Public and private:** Anyone can see a public repository. Only invited people can see a private one; this catalogue only covers public code.
- **Archived:** Read-only. The project is kept for reference but is no longer changed.
