# Guided tours and tutorials

Tours follow a persona's journey through the catalogue. Tutorials walk through one task. Start either from the catalogue's user guide, under Start here.

## Tours by persona

### Policy lead: From a policy question to the right team

1. **Arrive** (home view): Opens the catalogue from a link.
2. **Orient** (discover view): Picks 'What are you interested in?' or searches in everyday words.
3. **Narrow** (discover view): Filters to 'being worked on' and their sector.
4. **Understand** (profile view): Opens a profile at Simple reading level.
5. **Connect** (family view): Follows 'who it belongs to' and raises an issue with the catalogue's maintainers.

### Data leader: From estate question to remediation plan

1. **Arrive** (insights view): Opens Insights and analytics.
2. **Assess** (dama view): Selects their knowledge areas on the DAMA wheel.
3. **Find debt** (legacy view): Opens Legacy and technical debt for their organisation.
4. **Compare** (family view): Looks at peers in the family tree and organisation profiles.
5. **Act** (legacy view): Downloads the CSV for a remediation plan.

### Service owner: Reuse before build

1. **Search** (search view): Searches everything for the capability.
2. **Check APIs** (apis view): Looks for an API and its catalogue entry.
3. **Check reuse** (profile view): Reads licence, care checklist and activity.
4. **Find guidance** (guidance view): Finds related playbooks and standards.
5. **Decide** (profile view): Records reuse, or contacts the owner.

### Repository owner moving from co-cddo: Move a co-cddo repository safely

1. **Learn** (start view): Reads the migration in six sentences.
2. **Locate** (repos view): Finds their repository and its proposed home.
3. **Check** (lineage view): Reviews dependencies and what breaks.
4. **Decide** (repos view): Records a decision.
5. **Move** (safe view): Follows GitHub's documented behaviour.

### Cross-government architect: Join the catalogue to govukOS

1. **Understand** (govukos view): Reads what each app holds and the shared key.
2. **Resolve ids** (govukos view): Uses the organisation crosswalk.
3. **Trace** (knowledge view): Follows lineage from source to check.
4. **Exchange** (knowledge view): Downloads feeds and vocabularies.
5. **Link** (govukos view): Uses the link scheme from other apps.

### Engineering and security lead: Raise the standard of public code

1. **Baseline** (practice2 view): Opens Good practice across disciplines.
2. **Find gaps** (practice2 view): Filters by type and sector.
3. **Check debt** (legacy view): Finds retired libraries.
4. **Check rules** (gdsway view): Checks against the GDS Way.
5. **Track** (practice2 view): Re-checks after the next scan.

## Tutorials

### New to GitHub

**Find code about a topic in everyday words.** Find projects about something you care about without knowing GitHub's words.

1. **Type what you're looking for** (search view): Use everyday words, such as 'benefits', 'school data' or 'maps'. The thesaurus also finds the technical words for them.
2. **Narrow it down** (search view): Choose what kind of thing you want back: projects, organisations, topics, APIs, words and more.
3. **Read the results** (search view): Results are grouped by kind, best match first. Select one to open it.
4. **How search works** (search view): This explains how results are ranked, so you know why something came first.

**Read a project's profile.** Understand what a project does, who it belongs to and whether it's looked after.

1. **The project at the top** (profile view): Its name in plain English, with the GitHub name underneath. Listen to it with the read-aloud button if that helps.
2. **At a glance** (profile view): Whether it's live, how recently someone changed it and who publishes it.
3. **Who it belongs to** (profile view): The chain from the GitHub account up to the government department.
4. **How well it's looked after** (profile view): A simple checklist: description, licence, recent changes, security and tests.
5. **Words explained** (profile view): Any technical word on this page, explained in a sentence.

**Find who a project belongs to.** Go from a department to the organisations and GitHub accounts where its code lives.

1. **Find an organisation** (family view): Type a department or public body. Matches come from GOV.UK's list of organisations.
2. **The family tree** (family view): Each department with the organisations under it. Open a branch to see more.
3. **The selected organisation** (family view): Its GitHub accounts, its projects and how much of its code is still being worked on.

### Intermediate

**Explore projects with filters.** Use filters, sorting and grouping to find work you could reuse.

1. **Start with an interest** (discover view): Pick a topic tile to start, or skip to searching.
2. **Search in everyday words** (discover view): Type words; the line under the box shows which related words were also searched.
3. **Filter by sector** (discover view): Keep only health, education, justice or another sector. Other filters show live projects, reusable ones or those with legacy signals.
4. **Sort and group** (discover view): Sort by recent work, name or size, and group by sector, kind or organisation.
5. **The projects** (discover view): Each card says what the project is in plain English. Open one for its full profile.

**See patterns across the estate.** Use the dashboard to answer estate-wide questions, then check the numbers behind each chart.

1. **Filter the whole dashboard** (insights view): Choose a sector, kind of body, topic or data management area; every chart follows.
2. **Growth over time** (insights view): New code projects each year, coloured by whether they are still worked on today.
3. **Who publishes most** (insights view): The organisations with most public code. Select a bar to open that organisation.
4. **Legacy at a glance** (insights view): Where legacy technology and technical debt show up. Every chart has 'Show the numbers' for a table.

**Check good practice against the GDS Way.** Judge how well code is looked after and where it falls short of the GDS Way.

1. **Practice across government** (practice view): Signals such as licences, security policies, tests and automated checks, by organisation.
2. **GDS Way checks** (gdsway view): Each co-cddo repository checked against the GDS Way, with the evidence for each result.
3. **Moving safely** (safe view): GitHub's recommended order for changes that can break things.

**Go from a data management activity to the tools that deliver it.** Find what an activity involves, the UK guidance for it, and the tools and code that deliver it.

1. **Choose a knowledge area** (dmbok view): The eleven areas of the DAMA wheel come first, then five DMBOK2 topics beyond it. Each card shows how many activities and tools it has.
2. **Find the activity** (dmbok view): Filter by phase, lifecycle stage or whether tools deliver it, or search in your own words, such as 'lineage' or 'retention'.
3. **Read the activity** (dmbok view): What it is, its deliverables, who does it, how it is measured, the UK guidance that applies, and the tools and code that deliver it.
4. **See it across the data lifecycle** (dmbok view): How many activities act at each stage, from planning to disposal. Select a number to list them.

**Find out who uses a tool, for what, where and when.** See the evidence that a tool is used in the public sector, and by whom.

1. **Find the tool** (tooling view): Filter by knowledge area, activity, lifecycle stage, type, evidence or the buyer's sector, then sort by the evidence you care about.
2. **Read who uses it** (tooling view): Case studies from the supplier's own site, tender and contract notices with buyer, date, value and supplier, public code, and G-Cloud listings.
3. **See who buys what** (tooling view): Notices by knowledge area and the buyer's sector. Select a number to filter the tools.
4. **Find the buyers** (tooling view): The public bodies with the most notices for these tools, and which tools they named.

### Advanced

**Find legacy technology and technical debt.** Locate legacy signals by organisation and sector, and export the evidence.

1. **The signals** (legacy view): Each signal, such as retired libraries or code nobody has changed for years, with how many projects show it.
2. **Filter** (legacy view): Narrow by sector, organisation, live projects or the core signals only.
3. **The projects** (legacy view): Every project with its signals and the evidence for each.
4. **Export** (legacy view): Download the filtered list as CSV for your own analysis.
5. **How accurate it is** (legacy view): How the signals are found and how precise they were on a checked sample.

**Reuse the knowledge graph and vocabularies.** Find any item's connections and download the vocabularies in open formats.

1. **The knowledge layer** (knowledge view): A graph, lineage, vocabularies, an ontology, a data dictionary and a thesaurus, as tabs.
2. **Find an item** (knowledge view): Search the graph for a project, organisation, topic or requirement and see what it connects to.
3. **Download** (knowledge view): Every part downloads in open formats: JSON-LD, SKOS, OWL, PROV and CSV.

**Join the catalogue to other apps.** Use the organisation feeds and crosswalk to join this catalogue with other apps.

1. **How the apps join** (govukos view): Every app can join on one key: the GOV.UK organisation slug.
2. **The feeds** (govukos view): Download organisation and repository feeds as JSON, CSV or DCAT.
3. **The crosswalk** (govukos view): Other apps' organisation ids matched to GOV.UK slugs, with the reason for every gap.
